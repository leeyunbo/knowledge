가장 단순한 동시성 패턴

생산자 스레드가 일을 만들고 소비자 스레드가 일을 처리해요. 그 사이에 BlockingQueue가 끼어요. 한쪽이 느려도 큐가 완충 역할을 해요. 자바 동시성에서 가장 자주 나오는 패턴이고, 이 패턴 위에 거의 모든 비동기 처리가 얹혀 있어요. 

BlockingQueue<Task> queue = new ArrayBlockingQueue<>(1000);

// Producer
new Thread(() -> {
    while (true) {
        Task t = generate();
        queue.put(t);
    }
}).start();

// Consumer
new Thread(() -> {
    while (true) {
        Task t = queue.take();
        process(t);
    }
}).start();

네 가지 메소드의 의미

메소드큐 가득 / 빔반환
add / remove예외IllegalStateException / NoSuchElementException
offer / poll즉시 포기false / null
offer(t, unit) / poll(t, unit)대기 후 포기false / null
put / take무한 대기인터럽트로만 깨어남

어떤 걸 골라야 하나요

  • throughput 우선, 손실 허용: offer / poll. 빠르지만 큐가 차면 항목이 떨어져요.
  • 안정성 우선, 무한 대기 허용: put / take. 손실은 없지만 graceful shutdown이 어려워져요.
  • 균형: offer(timeout) / poll(timeout). 가장 흔한 실무 선택이에요.

백프레셔(Backpressure)의 의미

소비자가 느린데 생산자가 빠르면 무한 큐에선 메모리가 터지고, 유한 큐에선 자연스럽게 흐름이 막혀요. 이 자연스러운 흐름 제어가 백프레셔예요.

유한 capacity의 큐는 백프레셔의 가장 단순한 형태예요. 큐가 차면 생산자가 멈춰요. 생산자가 외부 API라면 429로 응답하고, 사용자라면 화면에 대기를 보여줘요. 시스템이 자기 페이스로 일해요.

큐가 가득 찼을 때 처리 옵션

  1. 차단: put으로 생산자가 멈춰요. 가장 단순.
  2. 드롭: offer가 false면 항목 버리기. 로그·메트릭 같은 손실 허용 자리.
  3. 역압 전파: 생산자에게 신호를 돌려보내 속도를 줄이게 해요. Reactive Streams가 그 패턴.
  4. 우회: 다른 큐(DLQ)로 옮기거나 디스크에 적재.

생산자와 소비자가 여러 개일 때

BlockingQueue는 multi-producer multi-consumer가 안전해요. 단지 처리량은 큐의 락 방식에 따라 달라요.

  • ArrayBlockingQueue: 단일 락이라 동시 처리량이 낮아요.
  • LinkedBlockingQueue: put/take 별로 두 락을 써서 동시 처리량이 좋아요.
  • ConcurrentLinkedQueue: 락 없는 큐(BlockingQueue 아님)예요. 가장 빠르지만 take가 블록되지 않아요.

순서 보장

단일 생산자 + 단일 소비자에선 FIFO가 자연스럽게 지켜져요. 멀티 생산자가 되면 어느 producer의 항목이 먼저 들어갈지는 스케줄링에 달려 있어요. 같은 producer 안에서는 순서가 보장되지만, producer 간 상대 순서는 보장되지 않아요.

흔한 실수

1. 무제한 LinkedBlockingQueue

capacity 누락 시 OOM 위험. new LinkedBlockingQueue<>()는 안 돼요. 명시적으로 capacity를 줘요.

2. take를 try-catch 없이

take는 InterruptedException을 던져요. 잡고 어떻게 처리할지가 graceful shutdown의 핵심이에요. 다음 편에서 자세히 봐요.

3. 빠른 producer + 느린 consumer

큐 capacity가 너무 크면 메모리만 차고, 너무 작으면 생산자가 자주 멈춰요. P99 latency와 큐 평균 점유율을 보면서 조정해요.

면접에서 자주 나오는 자리

  • "백프레셔가 뭐예요?": 소비자가 느릴 때 생산자에게 자연스럽게 흐름을 줄여 달라는 신호예요. 유한 큐 + put이 가장 단순한 백프레셔예요.
  • "put과 offer 차이?": put은 무한 대기, offer는 즉시(또는 timeout) 시도예요. shutdown이 필요하면 offer(timeout)이 안전해요.
  • "멀티 producer 순서?": 같은 producer 안만 FIFO가 보장돼요. producer 간 상대 순서는 스케줄러에 달려 있어요.
