Set은 Map의 친척

자바의 Set 구현은 거의 다 Map 위에 얹은 거예요. 키만 쓰고 값은 더미를 두는 방식이에요. 그래서 Set과 Map의 시간 복잡도·특성이 거의 같아요. 

// HashSet 내부 (단순화)
public class HashSet<E> {
    private transient HashMap<E, Object> map;
    private static final Object PRESENT = new Object();

    public boolean add(E e) {
        return map.put(e, PRESENT) == null;
    }
}

HashSet → HashMap, LinkedHashSet → LinkedHashMap, TreeSet → TreeMap을 감싼 거예요. 2편의 Map 비교가 그대로 Set에 적용돼요.

HashSet, 기본 선택

"이 원소가 이미 있나요?"가 핵심 질문일 때 써요. contains·add·remove가 O(1)이에요. 순서가 필요 없으면 거의 항상 HashSet이에요.

LinkedHashSet, 중복 제거와 순서 보존

자주 쓰는 패턴이 있어요. "리스트에서 중복을 제거하면서 순서를 유지하고 싶다"예요. 

List<String> list = List.of("a", "b", "a", "c", "b");
List<String> unique = new ArrayList<>(new LinkedHashSet<>(list));
// [a, b, c]

HashSet으로 하면 순서가 망가져요. LinkedHashSet이 정답이에요.

TreeSet, 정렬과 범위 쿼리

Set인데 정렬도 필요하면 TreeSet이에요. NavigableSet 인터페이스로 floor/ceiling/headSet/tailSet 같은 강력한 쿼리를 O(log n)에 해요. 

TreeSet<Integer> ts = new TreeSet<>(Set.of(10, 20, 30, 40, 50));
ts.floor(25);    // 20 (25 이하 가장 큰)
ts.ceiling(25);  // 30 (25 이상 가장 작은)
ts.subSet(15, 35); // [20, 30]

List·Map·Set의 선택 기준

세 인터페이스 중 어디서 시작할지가 첫 결정이에요.

List, 순서가 있고 중복 허용

  • "순서대로 처리해야 한다."
  • "같은 값이 여러 번 들어갈 수 있다."
  • "인덱스로 접근한다."

→ ArrayList가 기본. Deque가 필요하면 ArrayDeque.

Set, 중복 없음

  • "어떤 원소가 이미 있는지 빠르게 알고 싶다."
  • "같은 값을 절대 두 번 넣지 않는다."

→ 순서 무관이면 HashSet, 입력 순서 보존이면 LinkedHashSet, 정렬·범위 쿼리면 TreeSet.

Map, 키-값 매핑

  • "어떤 키에 대응하는 값을 빠르게 찾고 싶다."
  • "키의 집합을 다룬다."

→ 순서 무관이면 HashMap, 삽입 순서·LRU면 LinkedHashMap, 정렬·범위 쿼리면 TreeMap.

한눈에 보는 결정 트리

동시성이 필요할 때

지금까지 본 컬렉션은 스레드 안전하지 않아요. 동시 접근이 필요하면 동시성 컬렉션을 써요.

일반동시성
HashMapConcurrentHashMap
TreeMapConcurrentSkipListMap
ArrayListCopyOnWriteArrayList (읽기 위주)
HashSetConcurrentHashMap.newKeySet()
TreeSetConcurrentSkipListSet

Collections.synchronizedXxx도 있지만 거의 안 써요. ConcurrentHashMap 계열이 동시성 시리즈에서 자세히 다룬 더 좋은 선택이에요.

변경 불가능 컬렉션 (Immutable)

자바 9부터 List.of, Map.of, Set.of 같은 팩토리 메소드가 들어왔어요. 변경 불가능하고, null을 허용하지 않고, 메모리 효율이 좋아요. 

List<String> l = List.of("a", "b", "c");
Map<String, Integer> m = Map.of("a", 1, "b", 2);
Set<Integer> s = Set.of(1, 2, 3);

// l.add("d");  // UnsupportedOperationException

상수, 설정값, 함수 인자처럼 변하지 않는 컬렉션은 이걸로 써요. 가독성·안전성 모두 좋아져요.

크기를 미리 알 때

컬렉션 크기를 알면 초기 용량을 지정해 grow/rehash 비용을 아껴요. 

// 1000개 들어갈 걸 알면
List<Integer> list = new ArrayList<>(1000);
Map<String, Integer> map = new HashMap<>(1024);

// HashMap은 load factor 고려:
// 실제 크기 = capacity * loadFactor (기본 0.75)
// 1000개 안전하게 들어가려면 capacity = 1334 이상
Map<String, Integer> m2 = new HashMap<>((int)(1000 / 0.75f) + 1);

면접에서 자주 나오는 자리

  • "HashSet과 TreeSet의 차이?": HashSet은 O(1)이지만 순서 없고, TreeSet은 O(log n)이지만 정렬돼요.
  • "LinkedHashSet은 언제?": 중복 제거 + 입력 순서 유지가 필요할 때요.
  • "List에서 중복 제거?": new ArrayList<>(new LinkedHashSet<>(list)) 또는 stream의 distinct()요.
  • "동시성 Set이 필요해요": ConcurrentHashMap.newKeySet()이 가장 일반적이에요.
  • "HashMap의 초기 용량을 어떻게 잡아요?": 예상 원소 수를 load factor(0.75)로 나눠 올림 + 1이에요. 자바 19부터 HashMap.newHashMap(n)이 이 계산을 해 줘요.

시리즈 마무리

1편에서는 ArrayList와 LinkedList를 비교하면서, Big-O가 같아도 캐시 효과로 실제 성능이 갈리는 걸 봤어요. 2편에서는 HashMap·LinkedHashMap·TreeMap을 두고 순서와 정렬이 선택을 가르는 자리를 짚었고요. 3편에서는 Set 구현과 List·Map·Set 사이의 선택, 동시성·불변 컬렉션, 초기 용량까지 정리했어요.

핵심은 단순해요. 순서가 필요한가, 정렬이 필요한가, 동시성이 필요한가를 묻고 답하면 자료구조가 정해져요. 헷갈리면 HashMap·HashSet·ArrayList가 기본 선택이에요. 그 외 구현은 명확한 이유가 있을 때만 꺼내요.
