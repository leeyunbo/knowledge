푸는 문제

CountDownLatch는 카운터가 고정되고 일회용이에요. CyclicBarrier는 재사용은 되지만 참여자 수가 고정이에요. 둘 다 부족한 자리가 있어요. 참여자가 실행 중에 추가·제거되는 자리, 여러 단계(phase)를 반복하면서 각 단계의 참여자가 달라지는 자리예요. 자바 7부터 들어온 Phaser가 이 자리를 풀어요.

기본 사용

Phaser phaser = new Phaser(3);  // 초기 참여자 3명

for (int i = 0; i < 3; i++) {
    executor.submit(() -> {
        for (int phase = 0; phase < 5; phase++) {
            doPhaseWork(phase);
            phaser.arriveAndAwaitAdvance();  // 도착 + 대기
        }
    });
}

주요 메소드

메소드의미
register()참여자 추가
arrive()도착 신호만. 대기는 안 함.
arriveAndAwaitAdvance()도착 + 다른 참여자 대기
arriveAndDeregister()도착 + 참여자에서 빠짐
awaitAdvance(phase)특정 phase가 끝나길 기다림
getPhase()현재 phase 번호
getRegisteredParties()현재 등록된 참여자 수

동적 참여 변경

실행 중에 참여자를 늘리거나 줄일 수 있어요. 

// 참여자 추가
phaser.register();

// 한 라운드 참여 후 빠지기
phaser.arriveAndDeregister();

스레드가 자기 일을 다 끝내면 deregister로 빠져서 남은 스레드들이 다음 phase로 갈 수 있게 해요.

Phase 종료 콜백

onAdvance를 오버라이드하면 각 phase가 끝날 때마다 콜백이 실행돼요. 

Phaser phaser = new Phaser(3) {
    protected boolean onAdvance(int phase, int registeredParties) {
        log.info("Phase {} done, {} parties", phase, registeredParties);
        return phase >= 5 || registeredParties == 0;  // 종료 조건
    }
};

반환값이 true면 phaser가 종료돼요. 모든 참여자가 deregister되어 0이 되면 자동 종료예요.

Latch / Barrier / Phaser 비교

도구재사용참여자 변경phase 콜백
CountDownLatchXX (고정 N)X
CyclicBarrierOX (고정 N)Runnable 1개
PhaserOO (register/deregister)onAdvance 오버라이드

흔한 자리

  • 다단계 병렬 계산: 각 단계의 참여 스레드가 달라지는 경우.
  • 워크플로우 동기화: 처음에 N명으로 시작했다 일부가 일을 끝내고 빠지는 흐름.
  • 테스트 동기화: 복잡한 시나리오에서 단계마다 다른 스레드가 참여.

흔한 실수

1. arrive 후 deregister 누락

스레드가 끝났는데 deregister를 안 하면 다음 phase가 영원히 그 스레드를 기다려요. arriveAndDeregister()로 마무리해요.

2. 너무 복잡한 사용

Phaser는 강력하지만 코드가 빨리 복잡해져요. CountDownLatch나 CyclicBarrier로 충분하면 그쪽이 가독성이 좋아요.

면접에서 자주 나오는 자리

  • "Phaser가 풀어 주는 자리?": 참여자가 동적으로 변하는 다단계 동기화예요. Latch + Barrier로 표현하기 어려운 자리에 써요.
  • "register / deregister?": 실행 중에 참여자를 추가하거나 빼는 메소드예요. Phaser의 핵심 기능이에요.
  • "언제 안 쓰는 게 좋아요?": 단순 fan-in은 CountDownLatch, 고정 N의 라운드는 CyclicBarrier가 더 깨끗해요. Phaser는 동적 참여가 진짜 필요할 때 써요.
