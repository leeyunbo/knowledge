왜 graceful shutdown이 까다로운가

ExecutorService를 만들기는 쉬워요. 종료가 까다로워요. 종료할 때 신경 써야 할 게 세 가지예요.

  • 현재 실행 중인 작업은 끝낼 시간을 줄 것인가, 강제로 끊을 것인가
  • 큐에 쌓여 있지만 아직 시작 안 한 작업은 어떻게 할 것인가
  • 새 작업이 들어오는 걸 막을 것인가

이 세 가지를 어떻게 조합하느냐가 graceful 종료냐, 즉시 종료냐를 결정해요. ExecutorService는 두 개의 메서드를 제공해요.

shutdown과 shutdownNow 비교

동작shutdown()shutdownNow()
새 작업 거부OO
실행 중인 작업끝까지 실행인터럽트 시도
큐에 있는 작업모두 실행실행 없이 List로 반환
반환값voidList<Runnable> (취소된 큐 작업)
블로킹 여부비동기 (즉시 리턴)비동기 (즉시 리턴)

중요한 포인트가 둘 다 비동기라는 거예요. shutdown()이 리턴됐다고 해서 ExecutorService가 끝난 게 아니에요. "더 받지 않겠다"고 선언했을 뿐, 이미 시작된 작업이나 큐 작업은 백그라운드에서 계속 돌아가요.

정말로 끝났는지 확인하려면 awaitTermination을 불러야 해요.

표준 종료 패턴

실무에서 자주 보는 패턴이에요. 정중하게 시도하다가 안 되면 강제로 끊는 2단계 구조예요. 

public void shutdown(ExecutorService es) {
    es.shutdown();    // 1. 새 작업 거부, 기존 작업은 계속

    try {
        // 2. 일정 시간 기다리기
        if (!es.awaitTermination(30, TimeUnit.SECONDS)) {
            // 3. 시간 안에 안 끝나면 강제 종료 시도
            List<Runnable> pending = es.shutdownNow();
            log.warn("강제 종료. 취소된 작업 {}개", pending.size());

            // 4. 강제 종료도 시간 좀 더 줘서 확인
            if (!es.awaitTermination(10, TimeUnit.SECONDS)) {
                log.error("ExecutorService가 끝까지 안 멈춤");
            }
        }
    } catch (InterruptedException e) {
        // 5. 우리 자신이 인터럽트되면 즉시 강제 종료
        es.shutdownNow();
        Thread.currentThread().interrupt();
    }
}

단계별로 정리하면 이래요.

  1. shutdown()으로 새 작업을 막고 기존 작업이 자연스럽게 끝나길 기다림
  2. awaitTermination으로 일정 시간 대기 (보통 30초~60초)
  3. 안 끝나면 shutdownNow()로 인터럽트를 보내 강제 종료 시도
  4. 그래도 안 끝나면 로그 남기고 포기 (정상적인 자바 코드라면 여기까지 거의 안 옴)
  5. 우리 스레드가 인터럽트되면 즉시 shutdownNow + 인터럽트 상태 복원

shutdownNow의 인터럽트가 의미하는 것

shutdownNow()는 마법처럼 스레드를 즉시 죽이는 게 아니에요. 실행 중인 각 스레드에 Thread.interrupt()를 호출할 뿐이에요. 이걸 받아서 실제로 멈추는 건 작업 코드의 책임이에요. 

// 인터럽트를 잘 처리하는 작업
public void runTask() {
    while (!Thread.currentThread().isInterrupted()) {
        try {
            doSomeWork();
            Thread.sleep(100);    // sleep은 InterruptedException 던짐
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();   // 상태 복원
            break;
        }
    }
}

작업이 sleep, wait, I/O 블로킹 같이 인터럽트를 받을 수 있는 호출을 안 하면 인터럽트 시그널은 그냥 플래그만 set돼요. 작업이 자기 의지로 isInterrupted()를 확인하지 않으면 멈추지 않아요.

무거운 계산 루프를 도는 작업이라면 주기적으로 isInterrupted()를 체크하는 코드를 넣어두세요. 안 그러면 shutdownNow가 와도 작업이 끝까지 계속돼요.

ThreadFactory 커스텀

ExecutorService를 만들 때 ThreadFactory를 따로 지정 안 하면 기본 팩토리가 쓰여요. 기본은 pool-1-thread-1 같은 이름을 줘요. 로그에서 어떤 풀의 스레드인지 분간이 안 가요.

실무 ExecutorService에는 항상 커스텀 ThreadFactory를 붙이는 게 좋아요. 신경 쓸 게 세 가지예요.

  • 이름: 로그·스레드 덤프에서 알아볼 수 있게. 풀의 역할과 인덱스가 보이도록.
  • 데몬 여부: JVM 종료 시 이 스레드들을 기다릴지 결정. 백그라운드 워커는 데몬, 메인 작업이면 non-daemon.
  • UncaughtExceptionHandler: 작업 코드에서 안 잡힌 예외가 올라왔을 때 처리.
ThreadFactory factory = new ThreadFactory() {
    private final AtomicInteger counter = new AtomicInteger(0);
    private final UncaughtExceptionHandler handler = (t, e) ->
        log.error("uncaught in {}", t.getName(), e);

    @Override
    public Thread newThread(Runnable r) {
        Thread t = new Thread(r);
        t.setName("payment-worker-" + counter.incrementAndGet());
        t.setDaemon(false);
        t.setUncaughtExceptionHandler(handler);
        return t;
    }
};

ExecutorService es = new ThreadPoolExecutor(
    10, 20, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100),
    factory,
    new ThreadPoolExecutor.AbortPolicy()
);

Guava의 ThreadFactoryBuilder를 쓰면 위 코드를 더 짧게 쓸 수 있어요. 

ThreadFactory factory = new ThreadFactoryBuilder()
    .setNameFormat("payment-worker-%d")
    .setDaemon(false)
    .setUncaughtExceptionHandler((t, e) ->
        log.error("uncaught in {}", t.getName(), e))
    .build();

Spring 환경에서는

Spring이 있으면 ThreadPoolTaskExecutor나 ThreadPoolTaskScheduler를 쓰는 게 일반적이에요. Lifecycle 관리(@PreDestroy에서 자동 graceful shutdown)와 ThreadFactory 설정을 빈 설정으로 깔끔히 묶을 수 있어요. 

@Bean(destroyMethod = "shutdown")
public ThreadPoolTaskExecutor paymentExecutor() {
    ThreadPoolTaskExecutor ex = new ThreadPoolTaskExecutor();
    ex.setCorePoolSize(10);
    ex.setMaxPoolSize(20);
    ex.setQueueCapacity(100);
    ex.setThreadNamePrefix("payment-");
    ex.setWaitForTasksToCompleteOnShutdown(true);
    ex.setAwaitTerminationSeconds(30);
    ex.initialize();
    return ex;
}

setWaitForTasksToCompleteOnShutdown(true)가 핵심이에요. 이걸 켜면 컨테이너 종료 시 자동으로 graceful 종료 시퀀스를 돌려줘요.

한 줄 요약

  • shutdown은 정중한 종료, shutdownNow는 인터럽트 강제 종료. 둘 다 비동기.
  • 실제로 끝났는지 확인하려면 awaitTermination으로 기다려야 해요.
  • 표준 패턴은 shutdown → 타임아웃 대기 → 안 되면 shutdownNow → 더 짧게 대기.
  • 인터럽트는 시그널일 뿐이에요. 작업 코드가 isInterrupted를 체크해야 실제로 멈춰요.
  • 운영 ExecutorService는 ThreadFactory에 이름·UncaughtExceptionHandler를 꼭 붙이세요.
