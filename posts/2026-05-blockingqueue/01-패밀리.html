BlockingQueue가 푸는 문제

생산자와 소비자가 서로 다른 속도로 일해요. 큐가 비었으면 소비자가 기다리고, 큐가 가득 차면 생산자가 기다려요. 이 자연스러운 흐름을 표준 인터페이스로 제공하는 게 BlockingQueue예요. 자바 동시성에서 가장 자주 쓰는 큐 추상이고, ThreadPoolExecutor·메시지 처리·이벤트 버스가 모두 위에 얹혀 있어요.

5가지 구현

구현크기특성

ArrayBlockingQueue

배열 기반 고정 크기 큐예요. 생성 시 capacity를 정해요. 락 하나로 put과 take를 모두 보호해서 구현이 단순해요. 공정성(fair) 옵션을 켜면 대기 스레드 순서대로 깨어나요. 

BlockingQueue<Task> queue = new ArrayBlockingQueue<>(100);
queue.put(task);     // 가득 차면 블록
Task t = queue.take(); // 비면 블록

메모리 사용이 안정적이라 백프레셔가 필요한 자리에 잘 맞아요. 큐 크기가 폭증할 일이 없어요.

LinkedBlockingQueue

연결 리스트 기반이에요. put과 take가 서로 다른 락을 써서 동시 처리량이 ArrayBlockingQueue보다 높아요. 다만 기본 크기가 Integer.MAX_VALUE라 사실상 무제한이에요. 명시적으로 capacity를 주지 않으면 OOM 위험이 있어요. 

BlockingQueue<Task> queue = new LinkedBlockingQueue<>(1000);  // 명시 권장

Executors.newFixedThreadPool이 내부에서 이걸 무제한으로 써요. 메모리 누수의 흔한 원인이에요. ThreadPoolExecutor 7인자 시리즈에서 다뤘던 그 함정이에요.

SynchronousQueue

내부에 항목을 저장하지 않아요. put은 누군가 take할 때까지 블록되고, 반대도 마찬가지예요. 생산자와 소비자가 직접 만나는 큐예요.

Executors.newCachedThreadPool이 이걸 써요. 스레드가 즉시 작업을 받아 처리하고, 없으면 새 스레드를 만들어요. 빠른 hand-off가 필요한 자리에 적합해요.

PriorityBlockingQueue

힙 기반이라 항상 가장 우선순위 높은 항목이 먼저 take돼요. Comparable을 구현한 객체나 Comparator를 함께 줘야 해요. 

BlockingQueue<Task> queue = new PriorityBlockingQueue<>(11,
    Comparator.comparingInt(Task::priority).reversed());

무제한이라 메모리에 주의해야 해요. 우선순위가 낮은 항목이 영원히 take되지 않으면 starvation이 생겨요. 같은 우선순위 안에서는 순서가 보장되지 않아요. FIFO가 필요하면 (priority, timestamp)로 묶어 비교해요.

DelayQueue

Delayed 인터페이스를 구현한 항목만 받아요. 만료 시간이 지난 항목만 take할 수 있어요. 만료 안 된 항목은 큐에 있어도 안 보여요. 

class ScheduledTask implements Delayed {
    private final long executeAt;

    public long getDelay(TimeUnit unit) {
        return unit.convert(executeAt - System.currentTimeMillis(),
            TimeUnit.MILLISECONDS);
    }

    public int compareTo(Delayed other) {
        return Long.compare(
            this.getDelay(TimeUnit.MILLISECONDS),
            other.getDelay(TimeUnit.MILLISECONDS));
    }
}

스케줄러·캐시 만료·재시도 대기 같은 자리에서 써요. ScheduledThreadPoolExecutor의 내부 큐가 DelayQueue 기반이에요.

면접에서 자주 나오는 자리

  • "Array와 Linked 차이?": Array는 단일 락에 고정 크기예요. Linked는 put/take 분리 락에 기본 무제한이라 capacity를 꼭 명시해야 해요.
  • "SynchronousQueue는 언제?": hand-off가 즉시 일어나야 하는 자리예요. CachedThreadPool의 기본 큐예요.
  • "PriorityBlockingQueue의 starvation?": 우선순위 낮은 항목이 계속 밀리면 영원히 take되지 않아요. aging이나 (priority, timestamp) 보완이 필요해요.
