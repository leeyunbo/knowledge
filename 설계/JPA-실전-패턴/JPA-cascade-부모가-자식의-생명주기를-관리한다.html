JPA cascade — 부모가 자식의 생명주기를 관리한다

설계 스터디 · JPA 실전 패턴 · 2026-03-30

✦
핵심 답변
cascade는 부모 엔티티의 영속성 변화를 자식에게 전파하는 설정이다. 부모를 저장하면 자식도 저장, 부모를 삭제하면 자식도 삭제.
◈
cascade 타입
타입동작사용 빈도
PERSIST부모 저장 시 자식도 저장자주 사용
MERGE부모 병합 시 자식도 병합가끔
REMOVE부모 삭제 시 자식도 삭제주의 필요
REFRESH부모 새로고침 시 자식도 새로고침드묾
DETACH부모 분리 시 자식도 분리드묾
ALL위 전부편하지만 위험할 수 있음
◉
실전 예시

cascade 없을 때

// 부모와 자식을 각각 저장해야 함
PointWallet wallet = new PointWallet(user);
walletRepository.save(wallet);

PointTransaction tx = new PointTransaction(wallet, ...);
transactionRepository.save(tx);  // 직접 save 필요

cascade = ALL 일 때

@OneToMany(cascade = CascadeType.ALL)
private List<PointTransaction> transactions = new ArrayList<>();

// 부모만 저장하면 자식도 자동 저장
wallet.charge(amount, transactionId);  // 내부에서 transactions.add()
// wallet의 dirty checking 시 새로 추가된 transaction도 INSERT됨
// transactionRepository.save() 불필요!

orphanRemoval과 함께

@OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
private List<PaymentCancel> cancels;

// orphanRemoval = true → 컬렉션에서 제거하면 DB에서도 DELETE
cancels.remove(0);  // → DELETE FROM payment_cancels WHERE id = ?

// orphanRemoval = false → 컬렉션에서 제거해도 DB에 남음
cancels.remove(0);  // → FK만 null로 변경
◆
언제 쓰고 언제 피하는가

cascade를 써야 하는 경우

자식이 부모 없이 존재할 수 없을 때 (생명주기가 같을 때)

// PointWallet ↔ PointTransaction
// → 지갑 없는 거래 내역은 의미 없음
// → 지갑에서 charge() 할 때 트랜잭션도 함께 생성
@OneToMany(cascade = CascadeType.ALL)
private List<PointTransaction> transactions;

// Payment ↔ PaymentCancel
// → 결제 없는 취소는 의미 없음
@OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
private List<PaymentCancel> cancels;

cascade를 피해야 하는 경우

자식이 독립적인 생명주기를 가질 때

// User ↔ PointWallet
// → User 삭제해도 Wallet은 남아야 할 수 있음 (잔액 정산 등)
// → cascade REMOVE 쓰면 User 삭제 시 Wallet도 삭제됨 → 위험
@OneToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User user;  // cascade 없음

// CouponEvent ↔ Coupon
// → 이벤트 삭제해도 발급된 쿠폰은 남아야 함
// → cascade 쓰면 안 됨

판단 기준 정리

질문YesNo

◉
CascadeType.ALL의 위험성

ALL은 REMOVE를 포함하기 때문에 의도치 않은 삭제가 발생할 수 있다.

// 안전한 선택: 필요한 것만 명시
@OneToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE})

// 편하지만 위험할 수 있는 선택
@OneToMany(cascade = CascadeType.ALL)
// → 부모 삭제 시 자식도 전부 삭제됨

확실히 생명주기가 같을 때만 ALL을 쓰고, 애매하면 PERSIST + MERGE만 쓰는 게 안전해요.
