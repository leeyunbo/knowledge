git stash 완벽 정리

Git · 기본 명령어 · 2026-03-23

✦
핵심 답변
git stash는 작업 중인 변경사항을 임시 저장소에 보관하고 워킹 디렉토리를 깨끗한 상태로 되돌리는 명령어다. 브랜치 전환이나 급한 핫픽스가 필요할 때 커밋하지 않고도 작업을 보존할 수 있다.

커밋하기엔 애매하고, 버리기엔 아까운 작업물을 잠깐 치워두는 것이다. stash는 스택(LIFO) 구조로 쌓이며, 나중에 원하는 시점에 꺼내서 다시 적용할 수 있다.

◈
알아야 할 배경 개념

Git의 세 가지 영역과 stash의 위치:

  • 워킹 디렉토리 — 실제 파일을 수정하는 곳
  • 스테이징 영역(Index) — git add한 변경사항
  • 로컬 저장소 — git commit한 스냅샷
  • Stash — 위 세 영역과 별도로 존재하는 임시 보관소. 스택 구조로 여러 개 쌓을 수 있다.

git stash를 실행하면 워킹 디렉토리와 스테이징 영역의 변경사항이 stash로 이동하고, 워킹 디렉토리는 마지막 커밋 상태로 돌아간다.

◉
더 깊이 파고들기

핵심 명령어 정리:

명령어설명
git stash변경사항을 stash에 저장하고 워킹 디렉토리를 clean 상태로
git stash -m "메시지"설명 메시지와 함께 stash 저장
git stash -uuntracked 파일(새로 만든 파일)까지 포함해서 stash
git stash liststash 목록 확인 (stash@{0}, stash@{1}, ...)
git stash pop가장 최근 stash를 꺼내서 적용하고 stash에서 삭제
git stash applystash를 적용하되 stash에서 삭제하지 않음
git stash apply stash@{2}특정 stash를 지정해서 적용
git stash drop stash@{1}특정 stash 삭제
git stash clear모든 stash 삭제
git stash show -pstash 내용을 diff로 확인

pop vs apply — 언제 뭘 쓰나?

  • pop — 일반적인 경우. 꺼내고 나면 stash에서 사라진다. "한 번 쓰고 끝"일 때.
  • apply — stash를 여러 브랜치에 적용하고 싶을 때. stash가 남아있으므로 반복 사용 가능.

실전 시나리오:

1. 급한 핫픽스가 들어왔을 때

# feature 브랜치에서 작업 중...
git stash -m "feature-login 작업 중"
git checkout main
git checkout -b hotfix/urgent-bug
# 핫픽스 작업 & 커밋 & 머지
git checkout feature/login
git stash pop   # 아까 작업하던 거 복원

2. 브랜치를 잘못 골라서 작업했을 때

# main에서 작업해버렸다...
git stash
git checkout feature/correct-branch
git stash pop   # 올바른 브랜치에서 복원

3. pull 전에 충돌 방지

git stash
git pull origin main
git stash pop   # 충돌 나면 수동 해결

주의사항:

  • git stash는 기본적으로 tracked 파일만 저장한다. 새로 만든 파일(untracked)은 -u 옵션을 붙여야 한다.
  • stash는 브랜치에 종속되지 않는다. A 브랜치에서 stash한 걸 B 브랜치에서 pop할 수 있다.
  • stash pop 시 충돌이 발생하면 stash가 자동 삭제되지 않는다. 충돌 해결 후 수동으로 git stash drop 해야 한다.
  • 장기 보관용이 아니다. 오래 쌓아두면 뭘 stash했는지 잊어버린다. -m으로 메시지를 남기자.
◆
시각화

git stash는 워킹 디렉토리와 스테이징 영역의 변경사항을 Stash 스택에 저장한다. git stash pop은 스택 최상단에서 꺼내 워킹 디렉토리에 복원한다.
