Nginx와 Apache httpd 완벽 비교

DevOps 인프라 · 웹서버 · 2026-03-26

✦
핵심 답변
둘 다 C로 작성된 웹서버이며, 정적 파일 서빙과 리버스 프록시가 가능하다. 핵심 차이는 요청 처리 아키텍처: Apache는 요청마다 프로세스/스레드를 할당하고, Nginx는 이벤트 루프로 비동기 처리한다.

흔한 오해: Apache httpd ≠ Apache Tomcat. Tomcat은 Java 서블릿 컨테이너이고, httpd는 C로 만든 범용 웹서버다. 이름만 같은 Apache 재단 소속일 뿐, 완전히 다른 소프트웨어.

◈
알아야 할 배경 개념

웹서버가 하는 일

웹서버의 핵심 역할은 두 가지다:

  • 정적 파일 서빙 — HTML, CSS, JS, 이미지 등을 클라이언트에게 전달
  • 리버스 프록시 — 클라이언트 요청을 백엔드 애플리케이션(Spring Boot, Django 등)으로 전달하고 응답을 돌려줌

프로세스 기반 vs 이벤트 기반

  • 프로세스/스레드 기반 (MPM) — 요청 1개 = 스레드 1개 할당. 직관적이지만, 동시 접속이 많아지면 메모리 사용량이 선형 증가
  • 이벤트 기반 (Event Loop) — 워커 프로세스 1개가 수천 개의 연결을 비동기로 처리. I/O 대기 중에도 다른 요청 처리 가능

C10K 문제

2000년대 초 화두가 된 문제: "서버 하나로 동시 10,000개 연결을 처리할 수 있는가?" Apache의 프로세스 모델로는 어려웠고, 이 문제를 해결하기 위해 Nginx가 2004년에 탄생했다.

더 깊이 파고들기

상세 비교

항목 Nginx Apache httpd
구현 언어 C C
아키텍처 이벤트 기반 (비동기, 논블로킹) MPM (prefork / worker / event)
동시 접속 워커 1개로 수천~수만 연결 처리 연결당 스레드/프로세스 → 메모리 비례 증가
정적 파일 성능 매우 빠름 (sendfile, zero-copy) 빠름 (Nginx보다 느림)
메모리 사용 적음 (고정적) 많음 (동시 접속에 비례)
설정 방식 nginx.conf — 간결한 블록 구조 httpd.conf + .htaccess — 디렉토리별 설정 가능
.htaccess 미지원 지원 — 서버 재시작 없이 디렉토리별 설정 변경
리버스 프록시 핵심 설계 목적. 설정 간단 mod_proxy 모듈로 지원 (가능하지만 덜 직관적)
모듈 로딩 컴파일 시 포함 (동적 모듈 일부 지원) 런타임 동적 로딩 (유연)
SSL/TLS 내장, 설정 간단 mod_ssl로 지원
시장 점유율 (2026) 1위 2위 (레거시 프로젝트에서 강세)
대표 사용처 리버스 프록시, API 게이트웨이, CDN, 로드밸런서 전통적 웹 호스팅, PHP 연동, .htaccess 필요한 환경

Apache가 더 나은 경우

  • .htaccess가 필요할 때 — 공유 호스팅 환경에서 사용자별 설정 분리
  • PHP-FPM / mod_php 레거시 — 기존 PHP 환경과의 호환성
  • 동적 모듈 로딩 — 런타임에 모듈을 켜고 끄는 유연성이 필요할 때

Nginx가 더 나은 경우

  • 리버스 프록시 / 로드밸런서 — 설계 자체가 이 용도
  • 정적 파일 서빙 — Vue, React 빌드 산출물 서빙에 최적
  • 높은 동시 접속 — 적은 리소스로 대량 연결 처리
  • 마이크로서비스 앞단 — API 라우팅, SSL 종단, 캐싱을 한 곳에서

실무 구성 예시: Vue + Spring Boot

Crispy 같은 프로젝트에서 Nginx를 사용하는 전형적인 구성:

# /etc/nginx/conf.d/crispy.conf
server {
    listen 80;
    server_name crispy.example.com;

    # Vue 빌드 산출물 (정적 파일)
    location / {
        root /home/cdhome/deploy/dist;
        index index.html;
        try_files $uri $uri/ /index.html;  # SPA 라우팅
    }

    # Backend API 프록시
    location /api {
        proxy_pass http://localhost:10099;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

try_files $uri $uri/ /index.html이 핵심 — Vue Router의 history mode에서 새로고침 시 404가 나는 문제를 해결한다. Apache에서는 mod_rewrite로 동일하게 설정 가능하지만, Nginx가 훨씬 간결하다.

시각화

요청 처리 아키텍처 비교

Apache는 요청마다 스레드를 할당하므로 동시 접속이 늘수록 메모리가 선형 증가한다. Nginx는 이벤트 루프에서 I/O 대기 중인 요청을 건너뛰며 처리하므로, 워커 수가 고정되어 있어도 수만 개의 연결을 처리할 수 있다.
