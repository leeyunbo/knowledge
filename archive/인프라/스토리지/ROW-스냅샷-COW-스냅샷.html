ROW 스냅샷 vs COW 스냅샷

개발자도 궁금한 IT 인프라 · SECTION3 스토리지 · 2026-03-26

✦
핵심 답변
COW(Copy-On-Write)는 데이터가 변경될 때 원본을 새 위치에 복사한 뒤 덮어쓰는 방식이고, ROW(Redirect-On-Write)는 변경된 데이터를 새 위치에 직접 기록하고 포인터만 바꾸는 방식이다. 둘 다 스냅샷의 "특정 시점 데이터 보존"이라는 목표를 달성하지만, 그 경로가 완전히 다르다.

스토리지에서 스냅샷(Snapshot)이란 특정 시점의 데이터 상태를 빠르게 보존하는 기술이다. 전체 데이터를 물리적으로 복사하면 시간과 공간이 막대하게 소모되므로, 실제로는 "변경이 발생했을 때만" 최소한의 작업을 수행하는 전략을 사용한다. 이 전략이 바로 COW와 ROW이다.

COW (Copy-On-Write) 스냅샷

스냅샷 생성 시점에는 아무 데이터도 복사하지 않는다. 이후 원본 데이터에 쓰기가 발생하면, 덮어쓰기 전에 원본 블록을 별도의 스냅샷 영역에 복사(Copy)해 둔 뒤, 원래 위치에 새 데이터를 기록한다.

  • Write 시 3단계: ① 원본 블록 읽기 → ② 스냅샷 영역에 복사 → ③ 원래 위치에 새 데이터 쓰기
  • 스냅샷 생성 자체는 거의 즉시 완료 (메타데이터만 기록)
  • 쓰기 시 추가 I/O가 발생하므로 Write Penalty가 존재
  • 원본 데이터의 물리적 위치가 변하지 않아 읽기 성능은 그대로 유지

ROW (Redirect-On-Write) 스냅샷

쓰기가 발생하면 원본 위치를 건드리지 않고, 새 데이터를 새로운 위치에 기록한 뒤 포인터(메타데이터)를 새 위치로 변경(Redirect)한다. 원본 블록은 스냅샷 데이터로 자연스럽게 보존된다.

  • Write 시 2단계: ① 새 위치에 데이터 쓰기 → ② 포인터를 새 위치로 업데이트
  • 복사 과정이 없으므로 Write Penalty가 없다
  • 데이터가 여러 위치에 흩어지면서 순차 읽기 성능이 저하될 수 있음 (단편화)
  • 포인터 맵 관리가 복잡해질 수 있으며, 스냅샷 삭제 시 공간 회수가 까다로움

스냅샷(Snapshot)이란?

특정 시점(Point-in-Time)의 데이터 상태를 보존하는 기술이다. 풀 백업(Full Backup)과 달리 전체 데이터를 물리적으로 복사하지 않기 때문에, 생성 속도가 빠르고 공간 효율이 높다. 스냅샷은 변경분(delta)만 관리하는 것이 핵심이다.

블록 스토리지 기초

스토리지는 데이터를 일정 크기의 블록(Block) 단위로 관리한다. 파일 하나가 여러 블록에 걸쳐 저장되며, 각 블록은 고유한 주소(LBA: Logical Block Address)를 갖는다. 스냅샷은 이 블록 단위로 동작한다.

메타데이터와 포인터

스토리지 시스템은 "어떤 데이터가 어디에 있는지"를 포인터 테이블(메타데이터 맵)로 관리한다. ROW 방식은 이 포인터를 조작하는 것으로 스냅샷을 구현하며, COW 방식은 원본 위치를 유지하면서 별도 영역에 복사본을 만든다.

Write Penalty

쓰기 작업 시 추가로 발생하는 I/O 오버헤드를 의미한다. COW에서는 "읽기 → 복사 → 쓰기"로 총 3번의 I/O가 필요하지만, ROW에서는 "쓰기 → 포인터 변경"으로 2번이면 된다.

COW의 Write Amplification 문제

COW 스냅샷이 여러 세대 쌓이면, 하나의 블록 변경에 대해 여러 스냅샷 레벨에서 복사가 연쇄적으로 발생할 수 있다. 이를 Write Amplification(쓰기 증폭)이라 하며, 스냅샷 수가 많을수록 쓰기 성능이 급격히 떨어진다. 이 때문에 운영 환경에서는 스냅샷 보유 수를 제한하는 것이 일반적이다.

ROW의 단편화(Fragmentation) 문제

ROW는 쓰기마다 새로운 위치에 데이터를 기록하므로, 시간이 지나면 원래 연속이던 데이터가 디스크 전체에 흩어진다. HDD 환경에서는 순차 읽기 성능에 치명적이며, SSD에서도 GC(Garbage Collection) 부담이 증가한다. 주기적인 공간 재배치(Defragmentation/Compaction)가 필요하다.

실제 스토리지 제품에서의 적용

제품/기술 방식 특징
VMware VMFS ROW VM 스냅샷에서 redo log로 변경분 리다이렉트
NetApp WAFL ROW 파일시스템 자체가 ROW 기반, 스냅샷이 네이티브

스냅샷 삭제와 공간 회수

COW: 스냅샷 영역에 복사된 블록만 삭제하면 되므로 공간 회수가 비교적 단순하다.

ROW: 삭제할 스냅샷의 블록이 이후 스냅샷에서도 참조되고 있는지 확인해야 하며, 참조 카운트(Reference Count) 관리가 필요하다. 여러 스냅샷이 체인으로 연결되어 있으면 삭제 시 병합(merge) 작업이 필요할 수 있다.

언제 어떤 방식을 선택하는가?

  • 읽기 중심 워크로드 → COW가 유리 (원본 위치 불변, 순차 읽기 보존)
  • 쓰기 중심 워크로드 → ROW가 유리 (Write Penalty 없음)
  • 스냅샷을 자주 생성/삭제 → COW가 관리 용이
  • 스냅샷을 장기 보존 → ROW가 쓰기 성능 저하 없이 유지
