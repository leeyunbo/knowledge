Mac Docker에서 --network host가 안 되는 이유와 host.docker.internal

DevOps 인프라 · Docker 네트워크 · 2026-03-22

✦
핵심 답변
Mac Docker는 VM 위에서 돌아가기 때문에 --network host가 Linux처럼 동작하지 않는다. 포트는 -p로 매핑하고, 호스트 접근은 host.docker.internal을 써야 한다.
◈
Linux vs Mac의 Docker 아키텍처 차이
LinuxMac (Docker Desktop)
Docker 실행 위치 호스트 OS 위에 직접 경량 Linux VM 위에
--network host 컨테이너가 호스트 네트워크를 직접 공유 VM의 네트워크를 공유 (호스트 Mac이 아님)
localhost = 호스트 PC = 컨테이너 자기 자신

Mac에서 Docker가 VM 위에서 돈다는 걸 모르면, --network host로 띄운 컨테이너가 왜 외부에서 안 보이는지 이해할 수 없다.

◉
더 깊이 파고들기

문제 상황 재현:

# 이렇게 띄우면 Mac에서 접근 불가
docker run -d --network host --name myapp myimage:latest

# 컨테이너 안에서는 정상
docker exec myapp wget -qO- http://localhost:10030  # ✅ 동작

# 호스트(Mac)에서는 안 됨
curl http://localhost:10030  # ❌ 연결 거부

해결 1: 포트 매핑 (-p)

# -p로 명시적 포트 매핑
docker run -d -p 10030:10030 --name myapp myimage:latest

# 이제 호스트에서도 접근 가능
curl http://localhost:10030  # ✅

해결 2: 호스트 접근 — host.docker.internal

컨테이너 안에서 호스트 Mac의 서비스(예: PostgreSQL)에 접근해야 할 때:

# ❌ 컨테이너 안에서 localhost는 자기 자신
DB_HOST=localhost

# ✅ host.docker.internal은 호스트 Mac을 가리킴
DB_HOST=host.docker.internal

host.docker.internal은 Docker Desktop이 제공하는 특수 DNS 이름으로, 컨테이너에서 호스트 머신을 가리킨다. Linux에서는 기본 제공되지 않지만, Docker 20.10+에서 --add-host 옵션으로 설정할 수 있다.
