Jenkins 파이프라인 — Poll SCM, Cron, 빌드 옵션 총정리

DevOps 인프라 · Jenkins CI/CD · 2026-03-22

✦
핵심 답변
Jenkins 파이프라인은 변경 감지 방식(Webhook vs Poll SCM)과 빌드 옵션(동시 실행 제한, 이전 빌드 중단 등)을 설정해야 한다.

트리거 방식은 Jenkins가 외부에서 접근 가능한지에 따라 결정되고, 빌드 옵션은 안정적인 배포를 위해 세팅한다.

◈
변경 감지: Webhook vs Poll SCM
방식동작장점단점
Webhook GitHub → Jenkins에 HTTP 요청 즉시 반응, 효율적 Jenkins가 외부에서 접근 가능해야 함
Poll SCM Jenkins → GitHub에 주기적 확인 외부 노출 불필요 주기만큼 딜레이

선택 기준: Jenkins가 공인 IP/도메인으로 외부에 노출되어 있으면 Webhook이 효율적이다. 내부망이나 로컬 환경이라면 Poll SCM을 쓴다. ngrok 같은 터널링도 가능하지만 운영 환경에서는 Webhook이 표준이다.

◉
Cron 표현식과 H(Hash) 
* * * * *
│ │ │ │ │
분 시 일 월 요일
표현식의미
* * * * *매 1분마다
*/5 * * * *5분마다 (0, 5, 10, 15분에 실행)
H/5 * * * *5분마다 (프로젝트별 해시로 분산)
0 * * * *매시 정각
0 2 * * *매일 새벽 2시

H(Hash)란?

프로젝트 이름을 해시해서 각자 다른 시점에 실행한다. */5는 모든 프로젝트가 0, 5, 10분에 동시에 polling해서 부하가 집중된다. H/5는 각 프로젝트가 서로 다른 시점(예: 2, 7, 12분 / 4, 9, 14분)에 실행돼서 부하가 분산된다.

Jenkins가 공식적으로 H 사용을 권장한다.

◆
파이프라인 빌드 옵션

켜야 하는 것:

옵션이유
Do not allow concurrent builds 배포 중 또 배포가 시작하면 꼬인다
Abort previous builds 빌드 중 새 커밋이 오면 이전 빌드를 즉시 중단. 어차피 구버전 배포는 낭비
Do not allow resume Jenkins 재시작 시 중간부터 이어하지 않고 처음부터 다시 도는 게 안전
오래된 빌드 삭제 빌드 기록이 무한히 쌓이면 디스크 낭비. 10~20개 유지

상황에 따라 선택하는 것:

옵션설명언제 필요한가
GitHub projectUI에서 레포 링크 연결편의 기능. 동작에 무관
Pipeline speed/durability빌드 로그 디스크 쓰기 빈도대부분 기본값으로 충분
Throttle builds일정 시간 내 빌드 횟수 제한프로젝트가 많거나 리소스 제한 있을 때
빌드 매개변수빌드 시 파라미터 입력 (브랜치, 환경 등)수동 배포나 환경 분기가 필요할 때
빌드 원격 유발외부 HTTP 요청으로 빌드 시작다른 시스템에서 빌드를 트리거할 때
◉
파이프라인 흐름

테스트 실패 시 배포하지 않고 기존 운영을 유지한다. 코드 수정 후 다시 push하면 파이프라인이 자동 재실행.
