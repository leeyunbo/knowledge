JaCoCo와 PIT의 측정 원리와 쓸모

테스트 · 테스트 품질 측정 · 2026-04-04

✦
핵심 답변
JaCoCo는 "코드가 실행됐는지"를 측정하고, PIT은 "테스트가 진짜 버그를 잡는지"를 측정한다. 둘은 보는 관점이 완전히 다르다.

JaCoCo(커버리지)가 높다고 테스트가 좋은 게 아니다. 커버리지 100%여도 assert가 하나도 없으면 아무것도 검증하지 않는 테스트다. PIT(뮤테이션 테스팅)은 이 허점을 찾아준다.

비유하자면:

  • JaCoCo = 시험 범위를 다 읽었는지 확인 (읽기만 하고 이해 못 했을 수도 있음)
  • PIT = 시험 문제를 살짝 바꿔서 진짜 이해했는지 확인
◈
알아야 할 배경 개념

코드 커버리지란?

테스트를 실행했을 때 프로덕션 코드 중 몇 %가 실행됐는지를 수치화한 것이다. 종류가 여러 가지다:

종류측정 대상예시
라인 커버리지코드 한 줄이 실행됐는가10줄 중 8줄 실행 → 80%
브랜치 커버리지if/else 분기를 모두 탔는가if-else 중 if만 탐 → 50%
메서드 커버리지메서드가 호출됐는가5개 중 4개 호출 → 80%

뮤테이션 테스팅이란?

프로덕션 코드를 일부러 망가뜨려서(뮤턴트), 테스트가 이걸 잡아내는지 확인하는 기법이다. 테스트가 뮤턴트를 잡아내면 "킬(kill)", 못 잡으면 "생존(survived)"이라 한다.

◉
더 깊이 파고들기

JaCoCo는 어떻게 측정하는가

JaCoCo는 바이트코드 인스트루먼테이션(bytecode instrumentation)으로 동작한다:

  1. 컴파일된 .class 파일의 바이트코드에 프로브(probe)를 삽입
  2. 테스트 실행 시 각 프로브가 "이 코드가 실행됐다"고 기록
  3. 실행 후 프로브 데이터를 수집해서 리포트 생성

즉, 소스 코드를 건드리지 않고 바이트코드 레벨에서 측정한다. 그래서 프로덕션 코드에 영향이 없다.

JaCoCo의 한계
아래 테스트는 JaCoCo 기준 100% 커버리지다. 하지만 아무것도 검증하지 않는다: 
@Test
void test() {
    credit.charge(100);
    credit.use(30);
    // assert 없음 — 결과가 70인지 -30인지 확인 안 함
}

PIT은 어떻게 측정하는가

PIT은 뮤테이션 연산자(mutator)를 적용해서 코드를 변형한다:

뮤테이션 연산자원본 코드변형된 코드 (뮤턴트)
조건 경계 변경if (balance < amount)if (balance <= amount)
조건 부정if (balance < amount)if (balance >= amount)
반환값 변경return true;return false;
메서드 호출 제거list.add(item);// 제거됨
수학 연산 변경a + ba - b

각 뮤턴트마다:

  1. 코드를 변형한다 (예: <를 <=로)
  2. 관련 테스트를 실행한다
  3. 테스트가 실패하면 → 킬(KILLED) = 테스트가 이 변형을 감지했다
  4. 테스트가 통과하면 → 생존(SURVIVED) = 테스트가 이 변형을 못 잡았다
  5. 테스트가 아예 실행 안 됐으면 → NO_COVERAGE = 테스트가 닿지도 않는 코드
PIT이 잡아내는 것
아까 assert 없는 테스트? PIT이 balance -= amount를 balance += amount로 바꿔도 테스트가 통과한다. → SURVIVED → "이 테스트는 잔액 계산을 검증하지 않는다"를 알려준다.

실제 사례: 우리 프로젝트에서 일어난 일

발견된 문제도구내용
경계값 누락 PIT balance < amount에서 <를 <=로 바꿔도 테스트 통과 → balance == amount일 때 테스트가 없었음
부수 효과 미검증 PIT repurposeStatusService.completeContent() 호출을 제거해도 테스트 통과 → verify()로 호출 검증을 안 하고 있었음
미도달 코드 PIT findRepurpose의 예외 생성 람다가 NO_COVERAGE → 실패 케이스 테스트가 아예 없었음

그래서 쓸모가 있는가?

JaCoCoPIT
알려주는 것어디를 테스트 안 했는지테스트가 얼마나 믿을 만한지
못 알려주는 것테스트가 제대로 검증하는지어떤 테스트를 작성해야 하는지
비용거의 없음 (빌드 +1초)높음 (뮤턴트 수 × 테스트 수)
쓰는 방식빌드 게이트 (80% 미만이면 실패)리뷰 도구 (생존 뮤턴트 확인)
실무 채택률높음 (대부분의 팀)낮음 (품질에 민감한 팀)
결론
JaCoCo = 최소 안전망. "테스트 안 짠 코드가 있다"를 방지.
PIT = 품질 검증. "테스트가 진짜 동작하는지"를 확인.

둘 다 있으면 좋지만, JaCoCo 없이 PIT만 쓰는 건 의미 없고, JaCoCo만으로는 테스트 품질을 보장할 수 없다.
